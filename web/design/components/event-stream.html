The reconnect marker is a feature, not a diagnostic. A WebSocket pins to one API replica; a rolling update or a closed laptop cuts it. The client reconnects with from_offset = last seq + 1 and the server replays from the table — Follow has no "catch-up" path distinct from the live one, it only ever reads the table, and NOTIFY merely says when to re-read. The marker states the resumption and the fact that nothing was lost, because silently losing events is the one failure an audit tool must never hide.

Left edge, not row fill. changed and failed mark a 2px inset bar so a dense column stays scannable without the page turning into a colour field. Only failed additionally tints its row — it is the one state that should stop the eye.

No diffs here. The stream deliberately omits --diff payloads: they live in a separate table with its own access control because they contain rendered secrets. Viewing one is a distinct, separately authorised action.
